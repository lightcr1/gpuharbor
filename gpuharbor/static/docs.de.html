Überblick

GPUHarbor ist eine selbst gehostete Steuerzentrale für KI-Modelle auf RunPod. Es verwaltet einen Pod, lädt ein Modell und stellt es über eine OpenAI-kompatible API bereit.

Browser → GPUHarbor → RunPod-Pod → Runtime-Image → Modell

Der Controller braucht keine GPU. Er läuft auf einem kleinen Server; nur der Pod kostet Geld.

Erste Schritte

./scripts/install                          # lokal, nur HTTP
./scripts/install --bind-ip 10.10.40.100   # im LAN/VPN erreichbar
./scripts/setup                            # interaktiv mit Häkchen

Danach http://<ip>:8080 öffnen. Benutzer admin, Passwort aus GPUHARBOR_ADMIN_PASSWORD in .env.

Kostenpflichtige Aktionen sind standardmäßig gesperrt. Erst mit RUNPOD_ALLOW_BILLABLE_ACTIONS=true erreicht etwas RunPod.

Modelle

Ein „Modell" ist hier ein Profil: es beschreibt, welches Hugging-Face-Repository geladen wird, mit welcher Runtime, welchen Standardwerten und auf welchen GPUs. Die Gewichte sind nicht Teil von GPUHarbor; der Pod lädt sie beim ersten Start und legt sie auf seinem Volume ab.

GPUs

Das Dashboard lädt den echten RunPod-Katalog mit Verfügbarkeit und Preis. Ist die API nicht erreichbar, erscheint eine feste Liste.

WertBedeutung
NONEAktuell nirgends verfügbar; ein Start scheitert.
LOWWenig Kapazität, kann sich ständig ändern.
MEDIUM / HIGHGute Chancen.

Faustregel: FP8 oder BF16 brauchen etwa 1,3× der Modellgröße. Ein 27B-FP8-Modell ist rund 31 GB und passt auf 48 GB.

CUDA beachten: Images auf CUDA 12.x laufen nicht zuverlässig auf Karten, die CUDA 13 erwarten (z. B. Blackwell).

Regionen und Rechenzentren

Statt einen Standort zu wählen, wähle eine Region wie Europa oder Nordamerika. GPUHarbor fragt RunPod, welche Rechenzentren dazugehören, und weist automatisch eines zu. Ein konkretes Rechenzentrum bleibt im erweiterten Feld möglich.

Feste Liste in .env: RUNPOD_DATACENTER_IDS=EU-SE-1,CA-MTL-1.

Das Volume hängt am Rechenzentrum. Ein Standortwechsel bedeutet neuen Pod und neues Volume, der Modell-Cache wird also neu geladen.

Startoptionen

Beim Start überschreibbar, ohne das Profil zu ändern: Kontext, Sequenzen, GPU-Nutzung, GPU, Region bzw. Rechenzentrum und Volume.

Bei einem bestehenden Pod lassen sich nur Kontext, Sequenzen und GPU-Nutzung gefahrlos ändern. GPU, Rechenzentrum und Volume sind fest; dafür Pod löschen und neu erstellen. GPUHarbor merkt sich einen Profil-Fingerprint und verhindert stille Änderungen.

Löschen ist endgültig. Es ist die einzige Aktion, die alle laufenden Kosten beendet.

Kosten

  • GPU pro Stunde, je nach Karte (A40 ca. 0,49 USD/h).
  • Volume kostet weiter, auch wenn der Pod gestoppt ist. Das wird oft vergessen.
  • Download: der erste Start kostet mehrere Minuten bezahlte GPU-Zeit.

Der Idle-Stop beendet die GPU nach RUNPOD_IDLE_STOP_MINUTES ohne Verkehr. Die Volume-Kosten beendet er nicht.

Katalog & Updates

  • Mitgelieferte Profile sind schreibgeschützt; Änderungen werden Overrides.
  • Neue Built-ins erscheinen nach einem Update automatisch.
  • Eigene Profile bleiben unberührt. Export/Import als JSON im Dashboard.
  • Schreiben erfolgt atomar, die vorige Datei bleibt als .bak.

Runtimes erweitern

Eine Runtime besteht aus drei Teilen:

  1. Eintrag in registry/runtimes.json (ID, Label, Backend, GGUF).
  2. Dockerfile unter runtime/, das das Gateway auf Port 8000 bereitstellt.
  3. Unveränderlicher Image-Digest in .env (RUNTIME_IMAGE_*).

Ein wirklich neues Backend (nicht vLLM, llama.cpp oder Bonsai) braucht zusätzlich Code in runtime/gateway.py. Neue Modelle brauchen das nicht.

Runtime-Images sind absichtlich nicht im Browser änderbar: ein frei wählbares Image wäre beliebige Codeausführung.

Integrationen

Open WebUI und OpenHands sind optional und nutzen dieselbe OpenAI-kompatible API. Sie bekommen nur das MODEL_ACCESS_TOKEN, nie den RunPod-Key.

docker compose -f compose.yml -f compose.openwebui.yml up -d --build
docker compose -f compose.yml -f compose.openhands.yml up -d --build

OpenHands kann Code ausführen und Dateien ändern. Nur mit einem leeren, eigenen Arbeitsverzeichnis verwenden.

HTTPS

./scripts/setup
./scripts/install --bind-ip 0.0.0.0 --https 10.10.40.100 --tls-port 9443

Erzeugt eine lokale Zertifizierungsstelle in tls/ und einen TLS-Proxy. tls/local-ca.crt auf den Geräten importieren, dann https://10.10.40.100:9443/ öffnen. Setzt zusätzlich GPUHARBOR_COOKIE_SECURE=true.

Nicht ins Internet stellen. Nur LAN oder VPN.

Sicherheit

  • Kostenpflichtige Aktionen standardmäßig gesperrt.
  • Getrennte Geheimnisse für Steuerung, Inferenz und Runtime-Gateway.
  • Session-Änderungen brauchen CSRF; fehlgeschlagene Logins werden begrenzt.
  • RunPod-Antworten werden um Token- und Key-Felder bereinigt.
  • Runtime-Images müssen unveränderliche Digests sein.
