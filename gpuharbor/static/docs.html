Overview

GPUHarbor is a self-hosted control panel for AI models running on RunPod. It manages one pod, loads a model and serves it through an OpenAI-compatible API.

Browser → GPUHarbor controller → RunPod pod → runtime image → model

The controller needs no GPU. It runs on a small server or at home; only the pod costs money.

First steps

./scripts/install                          # local, HTTP only
./scripts/install --bind-ip 10.10.40.100   # reachable on LAN or VPN
./scripts/setup                            # interactive, with checkboxes

Then open http://<ip>:8080. User admin, password from GPUHARBOR_ADMIN_PASSWORD in .env.

Billable actions are locked by default. Nothing reaches RunPod until you set RUNPOD_ALLOW_BILLABLE_ACTIONS=true.

Models

A "model" here is a profile. It describes which Hugging Face repository to load, with which runtime, which defaults, and on which GPUs. The weights are not shipped with GPUHarbor; the pod downloads them on first start and caches them on its volume.

GPUs

The dashboard loads the real RunPod catalog with availability and price. If the API cannot be reached, a static list is shown instead.

ValueMeaning
NONENot available anywhere right now; a start will fail.
LOWLittle capacity. Can change any minute.
MEDIUM / HIGHGood chance of starting.

Rule of thumb: FP8 or BF16 need roughly 1.3× the model size. A 27B FP8 model is about 31 GB and fits on a 48 GB card.

CUDA matters. Runtime images built on CUDA 12.x do not reliably run on cards that expect CUDA 13, such as Blackwell.

Regions and datacenters

Instead of picking one location, choose a region such as Europe or North America. GPUHarbor asks RunPod which datacenters are in that region and assigns a free one. A specific datacenter is still available under the advanced field.

Fixed list in .env: RUNPOD_DATACENTER_IDS=EU-SE-1,CA-MTL-1.

The volume belongs to a datacenter. Changing location means a new pod and a new volume, so the model cache is downloaded again.

Launch options

These can be overridden per start without editing the profile: context, sequences, GPU utilisation, GPU, region or datacenter, and volume.

On an existing pod only context, sequences and GPU utilisation can change safely. GPU, datacenter and volume are fixed; delete and recreate the pod for those. GPUHarbor tracks a profile fingerprint and refuses a silent change.

Pod actions

ActionWhat happensCost
Check launch planShows the exact RunPod request with secrets removednone

Start podCreates or starts the pod; first start downloads the modelGPU hours
StopEnds GPU billing; the volume staysvolume

Deleting is final. It is also the only action that stops all remaining costs.

Costs

  • GPU is billed per hour and depends on the card (an A40 is around $0.49/h).
  • Volume keeps costing while the pod is stopped. This is the part people forget.
  • Download: loading a model the first time can take several minutes of paid GPU time.

The idle stop ends GPU billing after RUNPOD_IDLE_STOP_MINUTES without traffic. It does not stop volume costs.

Catalog and upgrades

  • Shipped profiles are read-only; editing one creates an override.
  • New shipped profiles appear automatically after an update.
  • Your profiles are never touched. Import and export JSON from the dashboard.
  • Writes are atomic and the previous file is kept as .bak.

More detail: docs/UPGRADES.md.

Adding runtimes

A runtime has three parts:

  1. An entry in registry/runtimes.json (id, label, backend, GGUF support).
  2. A Dockerfile under runtime/ that serves the gateway on port 8000.
  3. An immutable image digest in .env (RUNTIME_IMAGE_*).

A genuinely new backend (not vLLM, llama.cpp or Bonsai) also needs code in runtime/gateway.py. New models do not; a profile in the dashboard is enough.

Runtime images are intentionally not editable in the browser: a free choice of image would mean arbitrary code execution.

Integrations

Open WebUI and OpenHands are optional and use the same OpenAI-compatible API. They receive only MODEL_ACCESS_TOKEN, never the RunPod key.

docker compose -f compose.yml -f compose.openwebui.yml up -d --build
docker compose -f compose.yml -f compose.openhands.yml up -d --build

OpenHands can run code and change files. Use an empty, dedicated workspace.

HTTPS

./scripts/setup
./scripts/install --bind-ip 0.0.0.0 --https 10.10.40.100 --tls-port 9443

Creates a local certificate authority under tls/ and an nginx TLS proxy. Import tls/local-ca.crt on your devices, then open https://10.10.40.100:9443/. It also sets GPUHARBOR_COOKIE_SECURE=true.

Do not expose this to the internet. LAN or VPN only.

Security

  • Billable actions are locked by default.
  • Separate secrets for control, inference and the runtime gateway.
  • Session changes need a CSRF token; failed logins are rate limited.
  • RunPod responses are scrubbed of token and key fields.
  • Runtime images must be immutable digests.
