Overview

GPUHarbor is a self-hosted control panel for AI models running on RunPod. It manages one pod, loads a model and serves it through an OpenAI-compatible API.

Browser → GPUHarbor controller → RunPod pod → runtime image → model

The controller needs no GPU. It runs on a small server or at home; only the pod costs money.

First steps

Install, start and log in — in five steps:

  1. Install. In a terminal in the GPUHarbor folder: 
    ./scripts/install
    This writes the file .env with random secrets, starts GPUHarbor and prints the address. HTTPS is on by default. Add --webui for Open WebUI. For other machines use ./scripts/install --bind-ip <your-ip> or run ./scripts/setup for questions.
  2. Open the dashboard. https://localhost:8443. The certificate comes from a local CA, so the browser warns until you trust tls/local-ca.crt, see HTTPS.
  3. Log in. User admin. The password was generated for you. Show it with ./scripts/init-env --show-login or set a new one with --reset-password.
  4. Optional: store the RunPod key. Free read-only checks work right away: 
    ./scripts/set-runpod-key
  5. Only if you want to spend money. Set RUNPOD_ALLOW_BILLABLE_ACTIONS=true in .env and restart the controller.

The dashboard shows a Getting started checklist and a Connect an app card with the base URL, model name and API key. If something does not work, run ./scripts/doctor: it checks Docker, .env, the certificate and the containers and says what to fix.

What is .env, and how do I open it?

.env is a plain text file in the GPUHarbor folder. It holds your passwords and settings. The name starts with a dot, so it is hidden by default.

  • Terminal (Linux, macOS, WSL): 
    nano .env     # edit (save: Ctrl+O, Enter; leave: Ctrl+X)
cat .env      # only read
  • File manager: switch on "show hidden files" (usually Ctrl+H), then open .env.
  • Windows Notepad: File → Open, paste the full path (for example C:\gpuharbor\.env), then Open.

Find the line GPUHARBOR_ADMIN_PASSWORD=.... Everything after the = is your login password. Keep this file private.

Reach it from more devices

Only the local machine may connect at first. Add the address of a laptop or phone exactly as typed in the browser, then restart:

./scripts/add-host 192.0.2.10 --bind-ip 0.0.0.0
docker compose up -d

192.0.2.10 is the RFC 5737 documentation address — replace it with your own. List what is allowed: grep GPUHARBOR_TRUSTED_HOSTS .env.

Models

A "model" here is a profile. It describes which Hugging Face repository to load, with which runtime, which defaults, and on which GPUs. The weights are not shipped with GPUHarbor; the pod downloads them on first start and caches them on its volume.

GPUs

The dashboard loads the real RunPod catalog with availability and price. If the API cannot be reached, a static list is shown instead.

ValueMeaning
NONENot available anywhere right now; a start will fail.
LOWLittle capacity. Can change any minute.
MEDIUM / HIGHGood chance of starting.

Rule of thumb: FP8 or BF16 need roughly 1.3× the model size. A 27B FP8 model is about 31 GB and fits on a 48 GB card.

CUDA matters. Runtime images built on CUDA 12.x do not reliably run on cards that expect CUDA 13, such as Blackwell.

Regions and datacenters

Instead of picking one location, choose a region such as Europe or North America. GPUHarbor asks RunPod which datacenters are in that region and assigns a free one. A specific datacenter is still available under the advanced field.

Fixed list in .env: RUNPOD_DATACENTER_IDS=EU-SE-1,CA-MTL-1.

If the list only shows Automatic and Configured, the live RunPod catalog could not be read — usually because no RunPod key is stored yet. GPUHarbor then falls back to the fixed list in RUNPOD_DATACENTER_IDS. Add your RunPod key to see all real regions again.

The volume belongs to a datacenter. Changing location means a new pod and a new volume, so the model cache is downloaded again.

Launch options

These can be overridden per start without editing the profile: context, sequences, GPU utilisation, GPU, region or datacenter, and volume.

On an existing pod only context, sequences and GPU utilisation can change safely. GPU, datacenter and volume are fixed; delete and recreate the pod for those. GPUHarbor tracks a profile fingerprint and refuses a silent change.

Pod actions

ActionWhat happensCost

Deleting is final. It is also the only action that stops all remaining costs.

Costs

  • GPU is billed per hour and depends on the card (an A40 is around $0.49/h).
  • Volume keeps costing while the pod is stopped. This is the part people forget.
  • Download: loading a model the first time can take several minutes of paid GPU time.

The idle stop ends GPU billing after RUNPOD_IDLE_STOP_MINUTES without traffic. It does not stop volume costs.

Catalog and upgrades

  • Shipped profiles are read-only; editing one creates an override.
  • New shipped profiles appear automatically after an update.
  • Your profiles are never touched. Import and export JSON from the dashboard.
  • Writes are atomic and the previous file is kept as .bak.

Upgrade GPUHarbor

Your profiles live in the data volume and are never overwritten. To update:

git pull
./scripts/install        # keeps .env, rebuilds and restarts

Using a released image instead: docker compose pull && docker compose up -d.

The optional update hint is off by default. Turn it on under Settings in the header; then the controller asks the GitHub releases API once a day and shows an "update available" link.

More detail: docs/UPGRADES.md.

Adding runtimes

A runtime has three parts:

  1. An entry in registry/runtimes.json (id, label, backend, GGUF support).
  2. A Dockerfile under runtime/ that serves the gateway on port 8000.
  3. An immutable image digest in .env (RUNTIME_IMAGE_*).

A genuinely new backend (not vLLM, llama.cpp or Bonsai) also needs code in runtime/gateway.py. New models do not; a profile in the dashboard is enough.

Runtime images are intentionally not editable in the browser: a free choice of image would mean arbitrary code execution.

Integrations

Open WebUI and OpenHands are optional. Both talk to GPUHarbor's OpenAI-compatible API and receive only MODEL_ACCESS_TOKEN, never the RunPod key. The model pod must be running first.

Open WebUI (chat interface)

./scripts/install --webui

Open the Open WebUI link in the dashboard header (https://localhost:8444, or http://localhost:3000 with --no-https) and create the first account. The overlay already points Open WebUI at http://controller:8080/v1 and passes the token automatically. Pick the model by its served name from the profile (for example chat).

Running Open WebUI yourself? Add an OpenAI connection with base URL http://controller:8080/v1 and the value of MODEL_ACCESS_TOKEN as the API key.

OpenHands Agent Canvas (runs code)

mkdir -p workspace
./scripts/install --openhands

Open the OpenHands link in the dashboard header (https://localhost:8445). Nothing to configure: GPUHarbor writes an LLM profile for every model into OpenHands and activates the one for the running model. Profiles you made yourself are never touched. By hand, as the provider use openai/chat (or openai/code), base URL http://controller:8080/v1 and MODEL_ACCESS_TOKEN.

OpenHands can run code and change files. Use an empty, dedicated workspace.

PI coding agent (on your computer)

./scripts/install --pi      # or, any time: ./scripts/connect-pi

Adds your models to PI as the provider gpuharbor and checks that PI is installed. Only MODEL_ACCESS_TOKEN is used. The script can also add an optional /modelinfo command; it asks first. Details in docs/integrations/pi.md.

HTTPS

HTTPS is the default. ./scripts/install creates a local certificate authority under tls/ and an nginx proxy: the dashboard is at https://localhost:8443, Open WebUI at :8444 and OpenHands at :8445. The plain HTTP ports stay bound to this machine, so only TLS is reachable from the network. Session cookies are marked Secure.

Your browser warns until it trusts tls/local-ca.crt (import it as an authority in the browser or the system). For other devices:

./scripts/install --bind-ip 0.0.0.0 --https 192.0.2.10 --tls-port 9443

Use --no-https only for a throw-away test on localhost.

Do not expose this to the internet. LAN or VPN only.

Security

  • Billable actions are locked by default.
  • Separate secrets for control, inference and the runtime gateway.
  • Session changes need a CSRF token; failed logins are rate limited.
  • RunPod responses are scrubbed of token and key fields.
  • Runtime images must be immutable digests.
